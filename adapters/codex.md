# Codex adapter

Use the host's supported browser, document, mailbox and shell tools. Read their current instructions before use. CLI installation alone supplies no authenticated browser, upload or native desktop capability.

At setup record the agent version, OS (native Windows and WSL separately), available tools and actual observed checks for: local file access, TeX build, PDF extraction/rendering, browser navigation, form entry, test upload, mailbox access and optional native control. Values are verified, missing, unsupported or untested; include date, evidence and next action. Use synthetic local forms for checks; live mail sends require explicit test authorization. Reading a mailbox is distinct from sending mail.

If a host requires a concrete credential, CAPTCHA or agreement handoff, persist that exact remaining action and source of requirement. Standing campaign permission does not satisfy a tool that distinguishes action-time confirmation. Resume after the human completes it, without repeating finished phases or using another interface to evade the requirement.

Use native capabilities when available; a separately approved adapter may fill a missing capability only within its permissions. Preserve user profiles/tabs. Locked screen, idle sleep, native desktop and browser connectivity are distinct observations. Do not change power/security settings from an assumed diagnosis.

Official setup/capability references (recheck during setup): [CLI](https://developers.openai.com/codex/cli), [browser](https://learn.chatgpt.com/docs/browser), [Chrome extension](https://learn.chatgpt.com/docs/chrome-extension), [computer use](https://learn.chatgpt.com/docs/computer-use). Product doctor reports local tooling; the agent must record actual interactive capability checks.
