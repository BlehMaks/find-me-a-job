# Browser and authentication contract

## Bind and check

Select the explicitly authorized candidate workspace and browser profile. In managed mode bind profile/session to one client. Confirm expected account identity before opening an authenticated form. Do not export cookie jars or credentials to source, logs, feedback or another client.

Record separate observations for navigation, DOM interaction, native control, upload and mailbox. An extension connected does not prove a file upload works. Use a synthetic file and permitted test surface first. Keep tool documentation and mandatory confirmations in force.

## Operation protocol

1. Read checkpoint, canonical URL and exact opportunity ID; check no pending uncertain delivery.
2. Save entered fields, actual attachment filenames/hashes, visible validation and remaining steps privately. Omit passwords/codes and redact secret-bearing URLs.
3. Before dispatch, use `skills/applications/preflight.md` and the runtime's serialized operation/authority gate. A prepared message or filled form is not delivery.
4. Observe success/error/unknown without inventing a cause. If interrupted after dispatch may have occurred, mark delivery unknown. Reconcile portal history or message sent state before retrying; lack of email does not prove failure.
5. Save scope and evidence for blockers: operation, portal, profile/session, exact capability, observed/inherited, time, recheck/expiry and invalidating evidence. A working upload invalidates a broader historical upload assumption.

## Permitted recovery

Try a visible ordinary employer-provided alternative only when allowed: another upload control, supported file type within requirements, or an official full-text CV field. Preserve wording/attachments and verify resulting values. Do not prescribe settings changes unless evidence implicates them. Do not substitute unapproved backdoors or API requests for a required human action.

Reuse authorized existing accounts/sessions before registration. Prefer guest routes if they satisfy the application and policy. Store account/site/status and a private secret handle, never the secret value. Local untracked secret files are a minimal supported option with owner-only permissions; password managers are preferable when available. Do not print secrets to model-visible tool output. A human enters secrets where required by the active tool.

Group a shared login handoff once across affected applications, with exact URL, completed steps, attachments, missing action and resume point. Continue unrelated applications. Resolved questions leave the active handoff list but remain in history. Close inactive task-created tabs after saving state; preserve user tabs and the configured tab budget.
